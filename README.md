# دانلودر مکتب‌خونه (Maktabkhooneh Downloader)
ابزار خط فرمان برای دانلود ویدیوهای قابل‌دسترسی دوره‌های سایت [مکتب‌خونه](https://maktabkhooneh.org/) شامل ویدیوهای درس‌ها، فایلهای ضمیمه درس، زیرنویس ویدیو، به شکل همه با هم، یکجا و طبقه بندی شده. \
فقط محتوایی را می‌توانید دانلود کنید که قانوناً به آن دسترسی دارید.

## ✨ امکانات
- ورود و لاگین به سایت با ایمیل و پسورد و ذخیره کوکی در فایل نشست چندکاربره
- احراز هویت با کوکی از طریق متغییرهای محیطی
- **تشخیص خودکار API قدیم/جدید مکتب‌خونه** به ازای هر دوره (توضیح کامل در بخش زیر)
- تشخیص و انتخاب بهترین کیفیت ویدیوی درس مورد نظر، یا **انتخاب کیفیت دلخواه** با فلگ `--quality`
- **دانلود موازی** چند ویدیو هم‌زمان (`--parallel`)
- محدود کردن دانلود به **فصل‌های خاص** (`--chapters`)
- پوشه خروجی ثابت: `download/<نام دوره>`
- دانلود زیرنویس ویدیوها اگر موجود باشد، با همان نام پایه ویدیو (قابل غیرفعال‌سازی)
- دانلود فایل‌های ضمیمه درس، کنار ویدیو (قابل غیرفعال‌سازی)
- نمایش خلاصه پروفایل کاربر (وضعیت لاگین، ایمیل، اشتراک، خرید دوره)
- حالت نمونه‌گیری (Sample) با دانلود تنها N بایت اول هر ویدیو برای تست سریع
- **حالت `--dry-run`**: فقط لیست کردن آنچه دانلود می‌شود، بدون دانلود واقعی
- **گزارش نهایی CSV و HTML** از وضعیت هر واحد درسی (دانلودشده/قفل/ناموفق/...)
- **فایل لاگ** جداگانه برای دانلودهای طولانی/بدون نظارت
- **retry فقط موارد ناموفق** یک اجرای قبلی (`--retry-failed`)
- **بررسی صحت فایل‌های دانلودشده** بعد از اتمام کار (`--verify-integrity`)
- تخمین حجم کل دوره پیش از شروع دانلود (`--estimate-size`)
- ادامه دانلود از همان‌جا (Resume) در صورت قطع شدن یا اجرای مجدد
- Retry هوشمند روی خطای ۴۲۹ (Too Many Requests) با رعایت هدر `Retry-After`
- نوار پیشرفت دقیق: درصد + حجم دانلود شده / کل + سرعت تقریبی
- لاگ‌های رنگی و ایموجی برای خوانایی و تجربه بهتر

- ‏Node.js نسخه 18 یا بالاتر
- یک حساب کاربری در maktabkhooneh.org

## 🔄 تشخیص خودکار API قدیم/جدید (مهم)
مکتب‌خونه در حال انتقال تدریجی سایت به یک زیرساخت جدید (LMS) است. در این ساختار جدید:
- آدرس صفحه‌ی یک درس به‌جای `/course/<slug>/...` به شکل `/lms/course/<slug>/unit/<unitId>/` است.
- محتوای صفحه (ویدیو، زیرنویس، پیوست) دیگر داخل HTML نیست و از طریق API جیسون جداگانه بارگذاری می‌شود.

نکته‌ی مهم: **این انتقال هنوز روی همه‌ی دوره‌ها انجام نشده** — برخی دوره‌ها همچنان با ساختار قدیمی کار می‌کنند. به همین دلیل، این ابزار برای هر دوره به‌طور خودکار بررسی می‌کند از کدام روش استفاده کند:

1. برای اولین درسِ هر دوره، ابتدا API جدید را امتحان می‌کند.
2. اگر API جدید برای آن دوره وجود نداشت (یعنی دوره هنوز قدیمی است)، به‌صورت خودکار به روش قدیمی (استخراج از HTML صفحه) سوییچ می‌کند.
3. نتیجه‌ی این تشخیص برای کل همان دوره ذخیره (کش) می‌شود؛ یعنی این بررسی فقط یک‌بار در ابتدای کار هر دوره انجام می‌شود، نه برای تک‌تک درس‌ها — بنابراین سرعت کار افت محسوسی پیدا نمی‌کند.

نیازی نیست کاربر مشخص کند دوره‌اش قدیمی است یا جدید؛ ابزار خودش تشخیص می‌دهد.

## 🔐 ورود (Login) و نشست چندکاربره
دو راه اصلی:

1. استفاده از ایمیل و پسورد: (ساده و پیشنهاد می‌شود)
	 ```powershell
	 node download.mjs "https://maktabkhooneh.org/course/<slug>/" --user you@example.com --pass "Secret123" 
	 ```
	 در اولین ورود، کوکی (csrftoken + sessionid) در فایل پیش‌فرض `session.json` ذخیره می‌شود و دفعات بعد بدون نیاز به پسورد استفاده می‌گردد (مگر این که منقضی شود یا `--force-login` بزنید).
2. استفاده از کوکی آماده (Override):
	 اگر نمی‌خواهید پسورد را در خط فرمان بزنید، می‌توانید کوکی را به صورت دستی (مانند قبل) ست کنید تا لاگین خودکار نادیده گرفته شود.

### ساختار فایل نشست
فایل `session.json` به صورت چندکاربره است:
```jsonc
{
	"users": {
		"you@example.com": { "cookie": "csrftoken=...; sessionid=...", "updated": "2025-08-17T12:34:56.000Z" },
		"other@example.com": { "cookie": "csrftoken=...; sessionid=...", "updated": "2025-08-17T13:00:00.000Z" }
	},
	"lastUsed": "you@example.com"
}
```
در هر اجرا اگر `--user` مشخص کنید همان کاربر هدف قرار می‌گیرد، وگرنه آخرین کاربر استفاده شده بررسی می‌شود.

### اجبار ورود مجدد
اگر می‌خواهید با وجود معتبر بودن نشست، دوباره لاگین شود:
```powershell
node download.mjs "https://maktabkhooneh.org/course/<slug>/" --user you@example.com --pass "Secret123" --force-login 
```

## ⚠️ تنظیم کوکی (روش دستی قدیمی که پیشنهاد نمی‌شود!)

اگر ترجیح می‌دهید کوکی را دستی ست کنید یا لاگین مستقیم کار نکرد، مانند قبل کوکی `sessionid` (و بهتر: همراه csrftoken) را از مرورگر استخراج کنید.

بعد از اینکه به سایت maktabkhooneh.org لاگین شدید. روی صفحه راست کلیک کرده و inspect را بزنید. (یا CTRL+SHIFT+i بزنید) به تب Network بروید. صفحه را رفرش کنید. روی درخواست اول کلیک کنید. در سمت مقابل دنبال Cookie بگردید و آنجا چیزی که مهم است مقدار sessionid است و آن را کپی بگیرید.

![Get Cookies](https://github.com/user-attachments/assets/7943bed5-ffae-4075-a2ba-29f091d572b4)

دو روش برای تنظیم کوکی:
1) متغیر محیطی `MK_COOKIE`
2) یا قرار دادن مسیر فایل کوکی در `MK_COOKIE_FILE`

نکته: چون مقدار کوکی شامل کاراکترهایی مانند `;` و `=` است، حتماً مقدار را داخل کوتیشن قرار دهید.

### ویندوز – PowerShell
```powershell
# کوکی مستقیم
$env:MK_COOKIE = 'sessionid=...;'

# یا: مسیر فایل شامل کوکی
$env:MK_COOKIE_FILE = 'C:\\path\\to\\cookie.txt'
```

### ویندوز – CMD (Command Prompt)
```cmd
REM کوکی مستقیم
set "MK_COOKIE=sessionid=...;"

REM یا: مسیر فایل شامل کوکی
set "MK_COOKIE_FILE=C:\path\to\cookie.txt"
```

### لینوکس / مک – Bash/Zsh
```bash
# کوکی مستقیم
export MK_COOKIE='sessionid=...;'

# یا: مسیر فایل شامل کوکی
export MK_COOKIE_FILE="$HOME/cookie.txt"
```

نکته: اگر کوکی پیچیده یا چندخطی است، روش فایل (`MK_COOKIE_FILE`) توصیه می‌شود. البته در اینجا تک خطی است و همان تنظیم متغییر محیطی کفایت میکند.

## ▶️ اجرا
نمایش راهنما:
```powershell
node download.mjs --help 
```

اجرای دانلود:
```powershell
node download.mjs "https://maktabkhooneh.org/course/<slug>/" 
```

اجرای دانلود با ورود خودکار و ذخیره نشست:
```powershell
node download.mjs "https://maktabkhooneh.org/course/<slug>/" --user you@example.com --pass "Secret123" 
```

اجبار ورود مجدد:
```powershell
node download.mjs "https://maktabkhooneh.org/course/<slug>/" --user you@example.com --pass "Secret123" --force-login 
```

نکته: آدرس صفحه دوره‌ی مورد نظر را در دستورات فوق جایگزین کنید (چه از نوع قدیمی `/course/<slug>/` و چه از نوع جدید `/lms/course/<slug>/unit/<id>/`).

## 🧪 تست عملکرد
حالت نمونه‌گیری (مثلاً 64KB اول هر ویدیو):

```powershell
node download.mjs "https://maktabkhooneh.org/course/<slug>/" --sample-bytes 65536 --verbose
```

همچنین می‌توانید مقدار نمونه‌گیری را با متغیر محیطی ست کنید:
```powershell
$env:MK_SAMPLE_BYTES = "512000" 
node download.mjs "https://maktabkhooneh.org/course/<slug>/" 
```

## ⚙️ فلگ‌های کامل خط فرمان

| فلگ | توضیح | مثال |
|---|---|---|
| `<course_url>` | آدرس دوره (اجباری، اولین آرگومان بدون `--`) | `node download.mjs "https://maktabkhooneh.org/course/<slug>/"` |
| `--user` یا `--email` | ایمیل حساب کاربری برای لاگین | `--user you@example.com` |
| `--pass` یا `--password` | پسورد حساب کاربری | `--pass "Secret123"` |
| `--session-file <FILE>` | مسیر فایل نشست (پیش‌فرض: `session.json`) | `--session-file my-session.json` |
| `--force-login` | لاگین اجباری حتی اگر نشست ذخیره‌شده معتبر باشد | `--force-login` |
| `--sample-bytes <N>` | دانلود فقط N بایت اول هر ویدیو (حالت تست) | `--sample-bytes 65536` |
| `--quality <کیفیت>` | کیفیت دلخواه ویدیو؛ مقادیر مجاز: `1080p`, `720p`, `480p`, ...، یا `best`/`worst`. پیش‌فرض `best`. اگر کیفیت درخواستی موجود نبود، نزدیک‌ترین کیفیتِ **پایین‌تر** انتخاب می‌شود | `--quality 720p` |
| `--parallel <1-3>` | تعداد دانلود هم‌زمان (پیش‌فرض `1` یعنی صف تکی) | `--parallel 3` |
| `--chapters <بازه/لیست>` | محدود کردن دانلود به فصل‌های مشخص، با بازه (`3-5`) یا لیست (`2,4,7`) یا ترکیبی (`1-3,5,9-10`) | `--chapters 3-5` |
| `--no-subtitle` | رد کردن دانلود زیرنویس‌ها | `--no-subtitle` |
| `--no-attachments` | رد کردن دانلود فایل‌های پیوست | `--no-attachments` |
| `--no-log` | غیرفعال‌کردن فایل لاگ (پیش‌فرض فعال است) | `--no-log` |
| `--estimate-size` | تخمین حجم کل دوره قبل از شروع دانلود واقعی (پیش‌فرض غیرفعال، چون درخواست‌های اضافه می‌زند) | `--estimate-size` |
| `--dry-run` | فقط لیست‌کردن آنچه قرار است دانلود شود (بدون دانلود واقعی) + تولید فایل `dry-run-list.csv` | `--dry-run` |
| `--retry-failed` | فقط تلاش مجدد برای واحدهایی که در آخرین `report.csv` همین دوره با وضعیت `failed` ثبت شده‌اند | `--retry-failed` |
| `--verify-integrity` | پس از پایان دانلود، سایز فایل‌های نهایی را با سرور مقایسه می‌کند و برای هر فایل مشکوک/ناقص می‌پرسد دوباره دانلود شود یا نه | `--verify-integrity` |
| `--verbose` یا `-v` | لاگ‌های تفصیلی/دیباگ | `--verbose` |
| `--help` یا `-h` | نمایش راهنما | `--help` |

### مثال‌های ترکیبی
```powershell
# دانلود فقط فصل‌های ۳ تا ۵ با کیفیت 720p و سه دانلود هم‌زمان
node download.mjs "https://maktabkhooneh.org/course/<slug>/" --chapters 3-5 --quality 720p --parallel 3

# فقط دیدن اینکه چه چیزی دانلود می‌شود، بدون دانلود واقعی
node download.mjs "https://maktabkhooneh.org/course/<slug>/" --dry-run

# بعد از یک اجرای ناقص، فقط موارد ناموفق را دوباره امتحان کن
node download.mjs "https://maktabkhooneh.org/course/<slug>/" --retry-failed

# دانلود بدون زیرنویس و پیوست، با بررسی صحت فایل‌ها در پایان
node download.mjs "https://maktabkhooneh.org/course/<slug>/" --no-subtitle --no-attachments --verify-integrity
```

## 📊 گزارش‌های خروجی
همراه هر اجرا، فایل‌های زیر (در کنار پوشه‌ی دانلود همان دوره: `download/<نام دوره>/`) تولید می‌شوند:

| فایل | چه زمانی ساخته می‌شود | محتوا |
|---|---|---|
| `report.csv` | در پایان هر اجرای دانلود واقعی | فصل، عنوان درس، شناسه واحد، نام فایل، وضعیت (`downloaded`/`skipped-exists`/`locked`/`failed`/`no-video`)، حالت API استفاده‌شده، توضیح خطا (در صورت وجود) |
| `report.html` | همزمان با `report.csv` | همان اطلاعات، به‌صورت جدول رنگی و قابل مشاهده در مرورگر |
| `download.log` | در هر اجرا، مگر با `--no-log` غیرفعال شود | کپی کامل خروجی کنسول (بدون کدهای رنگی)، با برچسب زمانی هر خط — مناسب دانلودهای طولانی/بدون نظارت |
| `dry-run-list.csv` | فقط هنگام استفاده از `--dry-run` | لیست همان واحدها به همراه وضعیت در دسترس‌بودن/قفل‌بودن، بدون هیچ دانلود واقعی |

`report.csv` همچنین پایه‌ی کار `--retry-failed` است: اجرای بعدی، فقط ردیف‌های `failed` همین فایل را دوباره امتحان می‌کند.

## 📱 اجرا روی موبایل

### اندروید — با Termux (پیشنهادی)
[Termux](https://f-droid.org/packages/com.termux/) یک ترمینال لینوکسی واقعی برای اندروید است (از F-Droid نصب کنید، نه از Google Play که نسخه‌ی قدیمی و بی‌نگهداری دارد). چون Termux یک Node.js واقعی فراهم می‌کند، همین اسکریپت تقریباً بدون تغییر روی آن اجرا می‌شود:

```bash
# نصب Node.js داخل Termux
pkg update && pkg upgrade
pkg install nodejs git

# دسترسی به پوشه‌ی دانلودهای گوشی (اختیاری، برای اینکه فایل‌ها در اپ‌های دیگر هم دیده شوند)
termux-setup-storage

# دریافت پروژه
git clone https://github.com/HaamiData/maktabkhooneh-downloader.git
cd maktabkhooneh-downloader

# اجرا (دقیقاً مثل کامپیوتر)
node download.mjs "https://maktabkhooneh.org/course/<slug>/" --user you@example.com --pass "Secret123"
```
فایل‌های دانلودشده در همان مسیر پروژه، زیر پوشه‌ی `download/` قرار می‌گیرند. اگر می‌خواهید مستقیماً در پوشه‌ی Download گوشی ذخیره شوند، بعد از `termux-setup-storage` می‌توانید پروژه را داخل `~/storage/downloads/` اجرا کنید یا در پایان فایل‌ها را به آنجا کپی کنید.

### iOS — فعلاً پشتیبانی نمی‌شود
اپل اجازه‌ی اجرای Node.js مستقل (مثل Termux در اندروید) را در iOS نمی‌دهد، بنابراین این اسکریپت به همین شکل روی آیفون/آیپد قابل اجرا نیست.

راه‌حل واقعی برای iOS، ساخت یک رابط وب کوچک (اجرای همین منطق روی یک سرور/کامپیوتر همیشه‌روشن، و استفاده از گوشی فقط به‌عنوان مرورگر برای شروع/پیگیری دانلود) خواهد بود؛ این یک پروژه‌ی جداست و فعلاً در این مخزن پیاده‌سازی نشده. اگر به آن نیاز داشتید، به‌عنوان یک درخواست/Issue جداگانه مطرح کنید.

## 🔒 نکات امنیتی
- فایل `session.json` حاوی کوکی فعال و اطلاعات لاگین شماست؛ هرگز آن را به اشتراک نگذارید.
- از قراردادن پسورد خام در تاریخچه شل خودداری کنید (می‌توانید از یک اسکریپت موقتی یا متغیر موقت استفاده کنید).
- فایل‌های `report.csv` / `report.html` / `download.log` شامل عنوان دروس و مسیر فایل‌ها هستند، نه کوکی یا پسورد؛ ولی اگر دوره‌ی شما حساس/خصوصی است، این فایل‌ها را هم به‌اشتراک نگذارید.
